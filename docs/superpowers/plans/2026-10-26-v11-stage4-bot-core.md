# Этап 4 — ядро бота (план)

**Spec:** §5 (кроме ИИ и голоса), §9 «Права и бот», §4 (удаление, `/clear`), §7. Ветка `v1.1-bot` (от `v1.1` 9e4140a). `src/` не трогаем.
**Ledger:** `docs/superpowers/plans/v11-bot-progress.md` — строка на задачу с коммитом.

## Устройство

- `_shared/bot.ts` остаётся входом (`handleUpdate`, `BotStore`, `BotReply`) — `index.ts` и старые импорты не ломаются.
- Логика раскладывается в `_shared/bot/*.ts` (только `.ts`-импорты, без npm). Общий контекст `Ctx` (`bot/ctx.ts`): чат, автор, настройки, store, `now`, `today`, `uuid`, `send/edit/answer`, `notifyOwner`.
- Кнопки без состояния: `callback_data` ≤ 64 байт несёт id записи / первые 8 знаков id категории/счёта; подтверждения («Сохранить», вопрос про слово без суммы) заново разбирают исходный текст — из `reply_to_message.text` или из строки «🎤 Услышал: «…»»/«📝 «…»» в самом сообщении бота. Кнопки `/clear` и удаления по описанию несут минуту выдачи (живут 10 мин).
- `BotStore` дополняется общими `insert(table,row)`, `update(table,id,patch)`, `binned()` (строки корзины), `bin(ids,batch,at)`, `restore(ids)` (ставит `base_rev = rev`). Старые методы остаются.
- `handleUpdate(update, chats, store, now, uuid, opts?)`: `chats` — число (как 1.0, = владелец) или `{[chatId]: 'owner'|'partner'}`.
