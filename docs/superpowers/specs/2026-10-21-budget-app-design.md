# Seafarer Budget: спецификация

Дата: 2026-10-21
Статус: на ревью у Кирилла

## 1. Зачем

Личный учёт денег для одного человека, моряка с чередованием «контракт / отпуск». Приложение должно:

1. Показывать, куда уходят деньги: траты по категориям за месяц.
2. Помогать растянуть заработанное до следующего контракта: «можно тратить $Y в месяц».
3. Помогать копить на цели.
4. Следить за лимитами по категориям.

**Критерий успеха:** запись одной траты занимает 3–5 секунд (сообщение боту `кофе 80`), и через несколько секунд она видна в программе на ПК и в приложении на iPhone. Записи, сделанные без интернета, не теряются.

Пользователь один: Кирилл. Регистрации для других людей нет.

## 2. Компоненты

```
 Telegram-бот ──► Edge Function в Supabase ──┐
                                             ▼
                                  Postgres в Supabase
                                             ▲
 Программа для Windows (Tauri, .exe) ────────┤  синхронизация
 Приложение для iPhone (PWA) ────────────────┘
```

| Компонент | Технология | Что делает |
|---|---|---|
| Интерфейс | React + TypeScript + Vite | Один код для ПК и iPhone |
| Локальная база | IndexedDB (Dexie) | Полная копия данных на устройстве, работа офлайн |
| Программа для ПК | Tauri 2, установщик NSIS | `Seafarer-Budget-setup.exe` (на пользователя, без прав админа, без подписи) + портативный zip |
| Приложение для iPhone | PWA на GitHub Pages | Safari → «На экран Домой», полноэкранный режим, работает офлайн (service worker) |
| Облако | Supabase (бесплатный тариф): Postgres, Auth, Realtime, Edge Functions | Хранение, синхронизация, бот |
| Бот | Supabase Edge Function (Deno) + Telegram webhook | Разбор сообщений и запись в базу |
| Курсы | API НБУ (`bank.gov.ua/NBUStatService/v1/statdirectory/exchange`) через Edge Function `fx-rates` | Официальные курсы UAH к USD/EUR/MDL. Приложение не ходит в НБУ напрямую (CORS), а берёт курсы через функцию, которая кэширует их в `fx_rates` |

Сборка `.exe` идёт на GitHub Actions (`tauri-action`, Windows-раннер), поэтому Rust и Visual Studio Build Tools на компьютере ставить не нужно. Локальная сборка возможна как запасной вариант.

### Структура репозитория

```
budget/
  src/                         интерфейс (React)
    db/                        локальная база (Dexie) и синхронизация
    screens/                   экраны
  src-tauri/                   оболочка Windows-программы
  supabase/
    migrations/                SQL-схема, RLS, триггеры
    functions/
      _shared/                 общий код бота и приложения: парсер, расчёты, курсы
      telegram-bot/index.ts    webhook бота
  .github/workflows/           сборка .exe и выкладка PWA
  docs/
```

Код в `supabase/functions/_shared/` подключается в приложение через alias Vite. Так разбор текста `кофе 80` и расчёты работают одинаково в боте и в приложении.

## 3. Модель данных

Все таблицы в Postgres содержат `user_id uuid` (владелец), `rev bigint` (номер изменения, ставится триггером из общей последовательности при каждой вставке и обновлении) и `deleted boolean` (мягкое удаление). Ключи `id uuid` генерируются на клиенте, поэтому записи можно создавать офлайн.

**settings** (одна строка)
- `base_currency` = `USD`: в ней все итоги.
- `default_currency` = `UAH`: валюта, если в сообщении она не указана.
- `currencies` = `{UAH, USD, EUR, MDL}`: настраиваемый список. Новая валюта добавляется здесь, если НБУ публикует её курс.
- `accounts_mode`: `single` | `multi`.
- `status`: `home` | `contract`.
- `next_contract_date date null`: в режиме `home`.
- `contract_end_date date null`: в режиме `contract`.
- `salary_lag_days int` = 30: через сколько дней после посадки приходит первая зарплата.
- `contract_start_date date null`: в режиме `contract`, для «заработано за контракт».
- `timezone text` = `Europe/Kyiv`: по нему бот определяет «сегодня» и границы месяца.

**bot_updates** (служебная, только для функции бота): `update_id bigint` — уже обработанные сообщения Telegram, чтобы повторная доставка не создала дубль.

**accounts**
- `name`, `aliases text[]` (например `{нал, cash}`), `is_default bool`, `archived bool`, `sort int`.
- У счёта нет фиксированной валюты: баланс считается по каждой валюте отдельно, итог в USD.
- Всегда существует ровно один счёт с `is_default = true` («Основной»).

**categories**
- `name`, `kind` (`expense` | `income`), `icon` (эмодзи), `keywords text[]`, `archived`, `sort`.
- Набор по умолчанию. Расходы: Продукты, Кафе и рестораны, Транспорт и такси, Жильё и коммуналка, Связь и интернет, Здоровье, Одежда, Развлечения, Подарки, Путешествия, Авто, Документы и курсы, Прочее. Доходы: Зарплата, Прочий доход.

**transactions**
- `kind`: `expense` | `income` | `transfer` | `exchange` | `adjustment`.
- `amount numeric` (> 0, у `adjustment` со знаком), `currency`.
- `rate_usd numeric`: сколько USD в одной единице `currency` на дату записи.
- `amount_usd numeric`, `rate_pending bool`.
- `account_id`. Для `transfer`/`exchange` также `to_account_id`, `to_amount`, `to_currency`.
- `category_id` (у `expense`/`income`), `date date`, `note text`, `source` (`app` | `bot`), `created_at`.

**goals**: `name`, `target_usd`, `deadline date null`, `archived`.

**goal_moves**: `goal_id`, `amount_usd` (+ отложить, − забрать), `date`, `note`. Отложенное на цель не уменьшает баланс, а резервирует часть денег.

**limits**: `category_id`, `monthly_usd`.

**fx_rates** (общая таблица, без `user_id`): `date`, `currency`, `uah_per_unit`. Курс к USD считается как `uah_per_unit(cur) / uah_per_unit(USD)` на ту же дату.

### Режимы счетов

- `single`: интерфейс не показывает счета, все записи идут на счёт по умолчанию, показывается общий баланс.
- `multi`: видны счета, выбор счёта при вводе, переводы между счетами.
- Обмен валют (`exchange`) доступен в обоих режимах. В `single` он идёт внутри счёта по умолчанию (`to_account_id = account_id`).
- Переключение в обе стороны без потери данных. При переходе в `single` счета прячутся, новые записи идут на счёт по умолчанию, баланс показывается суммарно.
- Первый запуск: мастер спрашивает режим и стартовые остатки (по валютам или по счетам). Остатки записываются как `adjustment`.
- «Сверка» в любой момент: ввести реальную сумму, разница записывается как `adjustment`.

## 4. Расчёты

- **Баланс:** сумма по каждой валюте по всем незаархивированным счетам, перевод в USD по последнему известному курсу.
- **Отчёт по тратам:** суммы `amount_usd` (курс на дату траты) по категориям за месяц, сравнение с прошлым месяцем, топ-5 крупнейших трат.
- **Свободно:** `баланс_usd − Σ goal_moves`.
- **Можно тратить (режим `home`):** `дней = (next_contract_date + salary_lag_days) − сегодня`. В день: `свободно / дней`, в месяц: `в_день × 30.4`. Если дата не задана, показывается подсказка её указать. Если дней ≤ 0, показывается подсказка обновить статус.
- **Режим `contract`:** заработано за контракт, отложено в этом месяце (доходы − расходы), прогноз накоплений к `contract_end_date` при текущем темпе.
- **Цели:** прогресс `Σ goal_moves / target_usd`. Прогноз даты по среднему темпу за последние 90 дней. Если задан дедлайн, показывается, сколько нужно откладывать в месяц.
- **Лимиты:** траты категории за текущий месяц в USD против `monthly_usd`. Предупреждение, когда трата пересекает 80% и 100%.

## 5. Бот

**Доступ.** Принимаются только сообщения из чата, ID которого записан в секрете `OWNER_CHAT_ID`. Webhook проверяет заголовок `X-Telegram-Bot-Api-Secret-Token`. На чужие сообщения бот не отвечает. Запись в базу идёт ключом service role (он хранится только в секретах функции) от имени `OWNER_USER_ID`.

**Формат сообщения:** слова в любом порядке.
- **Сумма:** первое число (`80`, `80.5`, `80,5`).
- **Валюта:** `грн/гривен/uah/₴` → UAH; `usd/$/дол/долларов/бакс` → USD; `eur/€/евро` → EUR; `лей/леев/лея/lei/mdl` → MDL. Без валюты берётся `default_currency`.
- **Счёт** (только в `multi`): слово, совпадающее с `aliases` или именем счёта. Иначе счёт по умолчанию.
- **Дата:** слово `вчера` даёт вчерашний день. Иначе сегодня.
- **Доход:** `+` перед суммой либо слово из `keywords` доходной категории (`зп`, `зарплата`, `доход`).
- **Категория:** первое совпадение оставшихся слов с `keywords` (без учёта регистра, по началу слова). Если совпадения нет, трата сразу сохраняется в «Прочее» (ничего не теряется), и бот показывает кнопки, чтобы переложить её в нужную категорию. Первое слово описания добавляется в `keywords` выбранной категории, и в следующий раз бот угадает сам.
- **Сумма цели** в любой валюте переводится в USD по курсу дня.
- **Цели:** `цель <название> <сумма> [валюта]` откладывает, `цель <название> -<сумма>` забирает.
- Оставшийся текст записывается в `note`.

**Ответ:** `☕ Кафе и рестораны · 80 ₴ ($1.94)`, плюс строка лимита, если он задан: `Кафе за месяц: $62 из $100`, с ⚠️ после 80% и 🔴 после 100%. Под ответом кнопка «Отменить».

**Команды.** Telegram разрешает только латиницу, поэтому в меню команды с русскими описаниями. Слова без слэша тоже работают.
- `/today` или `сегодня`: траты за сегодня.
- `/month` или `месяц`: итог месяца по категориям.
- `/left` или `остаток`: свободно и сколько можно тратить.
- `/undo` или `отмена`: удалить последнюю запись из бота.
- `/help`: примеры.

**Ошибки:** сумма не найдена → ответ с примерами. Курс НБУ недоступен → запись сохраняется с последним известным курсом и `rate_pending = true`, точный курс подставляется позже.

## 6. Синхронизация

- Приложение всегда читает и пишет локальную базу (Dexie). Изменённые локально записи помечаются как `dirty`.
- **Push:** `upsert` всех `dirty` записей в Supabase. После успеха флаг снимается, а `rev` берётся из ответа.
- **Pull:** запрос записей с `rev > last_rev` по каждой таблице, применение локально, сохранение нового `last_rev`.
- **Конфликт:** выигрывает последнее записанное на сервер изменение. Для одного пользователя этого достаточно.
- **Когда синхронизировать:** при запуске, при возвращении в приложение, после каждого локального изменения (с задержкой 2 с), раз в 60 с, а также по событию Supabase Realtime. Благодаря последнему записи из бота появляются за секунды, пока приложение открыто.
- **Курсы:** при pull подтягиваются недостающие курсы за даты записей, а у записей с `rate_pending` пересчитываются `rate_usd` и `amount_usd`.
- **Индикатор:** ✓ синхронизировано / ⟳ ждёт отправки: N / офлайн.

## 7. Безопасность

- Вход через Supabase Auth, email и пароль, один раз на каждом устройстве. Сессия сохраняется.
- Регистрация новых пользователей в Supabase выключена после создания аккаунта Кирилла.
- RLS на всех таблицах с `user_id`: доступ только к строкам `user_id = auth.uid()`. Таблица `fx_rates` доступна на чтение всем вошедшим, на запись только через функцию.
- В коде приложения хранятся только URL проекта и anon-ключ. Они публичны по замыслу Supabase и защищены RLS. Токен бота и service role ключ лежат только в секретах Edge Function.
- Репозиторий может быть публичным (это нужно для бесплатного GitHub Pages), личных данных в нём нет.

## 8. Экраны

1. **Главный:** «свободно / можно тратить», баланс, быстрая строка ввода (`кофе 80`), последние записи, индикатор синхронизации.
2. **Добавить / изменить запись:** форма с суммой, валютой, категорией, датой, счётом (в `multi`) и заметкой.
3. **Отчёт:** месяц по категориям (круговая диаграмма и список), сравнение с прошлым месяцем, топ трат, переключение месяцев.
4. **Цели:** список с прогрессом, добавить цель, отложить или забрать.
5. **Лимиты:** полоски по категориям за текущий месяц.
6. **Счета** (в `multi`): балансы, перевод, обмен.
7. **Настройки:** режим счетов, статус дом/контракт и даты, валюты, категории, экспорт в CSV/Excel, выход.

Интерфейс на русском языке, светлая и тёмная тема, рассчитан на экраны iPhone и ПК.

## 9. Тестирование

- **Автотесты (Vitest):** парсер бота (все форматы из раздела 5), конвертация валют, расчёты из раздела 4, логика синхронизации с поддельным сервером (push, pull, конфликт, офлайн-очередь, мягкое удаление).
- **Проверка вживую:** сообщение боту → запись появилась на ПК и на iPhone. Запись офлайн на iPhone → появилась на ПК после возвращения связи. Установка `.exe` на чистый Windows-профиль.
